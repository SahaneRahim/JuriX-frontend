- `aria-pressed` sur la bascule : `Recherche` est la page courante ; la sémantique juste pour un lien courant est `aria-current="page"`, pas `aria-pressed` (la maquette l'écrit comme bouton). Recommandation : `<span aria-current="page">` pour `Recherche` et `<a>` pour `Assistant IA`.
- Soulignement des mots en gras sur 2 lignes : `background-size` sur un `<strong>` en ligne qui passe à la ligne : peindre le dégradé sur chaque fragment (`box-decoration-break: clone`) sinon la barre est étirée sur deux lignes. À tester avec un mot coupé en fin de ligne (chrome, safari).
- `line-clamp-2` + soulignement : le `-webkit-box` coupe `overflow:hidden` : un soulignement à `0 100%` sur la dernière ligne peut être rogné d'un pixel. Prévoir `padding-bottom:1px` ou `background-position: 0 calc(100% - 1px)`.
- `transition:slide` Svelte dans `/compare` : ne respecte pas `prefers-reduced-motion` seule ; et le rendu serveur ne l'exécute pas (inoffensif). La hauteur d'un tableau `display:table` (`lg:table`, `lg:table-fixed`) n'anime pas bien une hauteur de CELLULE ; la maquette utilise une grille CSS (`grid-template-rows`), pas une table. Le dépôt garde la sémantique `<table role="table">`. L'animation de hauteur doit donc se faire sur un `<div>` INTERNE à la cellule : OK avec `slide`. Ne pas réécrire la table en grille : les rôles ARIA seraient à refaire.
- `data-hors-du-bouton` sur le gréement : si on l'ajoute (niveau B), vérifier que le bouton flottant n'entre pas dans le champ de cartes à 1024 px.
- Le fléau de la maquette (`left:15%; right:15%`) à 1152 px donne 806 px ; les cartes sont `340 px`, `left:-170px` : à `<1024 px` : `300 px`. À 768 px, la page fait 768 − 48 = 720 px de contenu, donc le fléau (70 % = 504 px) est plus étroit que les 2 cartes (600 px) : elles se CHEVAUCHENT au milieu. La maquette ne montre ni 768 ni 1024 : vérifier avant de livrer le niveau B (`responsif.spec.ts` 768×1024, 1024×768).
- Pile de feuilles sous le champ : elle consomme 14 px de hauteur visuelle sous le champ ; `margin-top:22px` de la passerelle la compense dans la maquette. En écran court (740×360) : désactiver la pile (`court:` masque les `::before/::after`).
- README et `tests/e2e/README.md` se contredisent (adapter-node/`node build` vs adapter-vercel/`vite preview`) : lire `playwright.config.ts` avant de lancer les e2e.
- `docs` du dépôt : les commentaires parlent de « maquette recherche-p7a », « domaine-p11a », « recherche-vide-p7a » : ce sont les maquettes PRÉCÉDENTES du dépôt (propositions P7, P11), pas `RefonteRecherche`. Ne pas les confondre ; les décisions P7/P11 (une ligne, statut prouvé, pas de cote interne `PRC-…`, `data-hors-du-bouton`, 44 px) restent valables.
- Cote interne : aucun écran ne doit afficher `PRC-\d+` (tests `ux-recherche.spec.ts` L177, L199, `comparaison.spec.ts` L94 `LOI-2016-017`). La maquette n'en montre pas. Le piège est dans les squelettes et les `title=` : n'y mettre aucune cote.
- Aucune requête à l'API depuis le navigateur pour la recherche : `/search` est rendue par le serveur ; les animations ne doivent rien déclencher côté réseau (le dépôt a `data-sveltekit-preload-data="tap"` précisément pour éviter les recherches inutiles) : un survol de la bascule `Assistant IA` ne doit PAS précharger `/chat`.
