# A4 — Chaînes de l'interface (français, anglais) : règles, doublons, clés nouvelles

Ce fichier assemble les chaînes dont la refonte a besoin. **Source de vérité des clés existantes : `src/lib/stores/language.ts`** (blocs `fr` et `en`, `export const translations`). Source des textes de la maquette : `outils/textes-fr-brut.md` (extraction brute de chaque écran).

## 1. Règles du dépôt (à respecter pour toute chaîne)

- `$tr("zone.cle")` dans le balisage, `t("zone.cle")` dans le script (dans la page du chat, `tr` est importé sous le nom `traductions` à cause des `<tr>`). **Aucune chaîne affichée en dur** (sauf nom propre invariable comme « JuriX »).
- **Les blocs `fr` et `en` portent exactement les mêmes clés** : `src/lib/stores/language.test.ts` échoue sinon. Toute clé créée l'est dans les deux langues, dans la même PR.
- Deux fichiers recopient des phrases pour les tests unitaires et doivent suivre : `src/lib/components/chat/traductions-de-test.ts` (chat) et `src/lib/components/loi/dictionnaires-de-test.ts` (lecture, **les deux langues**).
- **Aucun français dans l'interface anglaise** (`monochrome.spec.ts` ouvre l'accueil et une loi en anglais : clé `jurix-language`). Aucune clé brute affichée (`ux-r2`).
- Typographie : espace fine insécable avant `?` `!` `;` `:` (U+202F) et dans les nombres (« 2 275 ») ; espace insécable (U+00A0) dans « n° 92/007 », « 14 août 1992 », « Art. 37 », « Section III : » ; apostrophe `’`. En anglais : pas d'espace avant `:` `?` `!`. **Les chaînes de ce document et des rapports sont écrites avec des espaces ordinaires** (le Markdown ne les distingue pas) : appliquer la typographie **en les écrivant dans `language.ts`, en séquences d'échappement comme le dépôt** (`'Trier par\u202F:'`, `'«\u202F{q}\u202F»'`, `'Profil\u00a0:'`). Le dépôt emploie les deux espaces selon les chaînes (`\u202F` dans les récentes `search.*`, `\u00a0` ailleurs) : pour les chaînes neuves, suivre la règle ci-dessus ; ne pas retoucher les chaînes existantes.
- Variables : `{n}`, `{profil}`, `{date}` remplies par `remplir($tr("clé"), { … })` (`$lib/components/listes/reperes`) — jamais `String.replace` avec un `$` dans la valeur. Nombres : `Intl.NumberFormat($language.current)`. Pluriels : deux clés (`…` / `…Un`) comme le dépôt le fait déjà.
- Nommage : `zone.sous.cle` ; zones neuves proposées : `accueil.champ.*`, `accueil.faq.*`, `accueil.preuves.*`, `chat.preuves.*`, `chat.puce.*`, `chat.carte.*`, `loi.ia.*` (existante), `loi.sommaire.*`, `loi.navigation.*`, `search.askAssistantQuery`.
- **Ne pas modifier le texte d'une clé que d'autres écrans ou tests lisent** sans mettre ces tests à jour : en particulier `loi.statut.origine` (lue par `StatutDuTexte.svelte` et recopiée dans `loi/dictionnaires-de-test.ts` ; le chat a sa propre famille `chat.statut.*`), `chat.progress.*`, `chat.disclaimer`, `a11y.searchField`, `search.button`.
- Les traductions **anglaises** ci-dessous sont des **propositions** : à faire relire par un anglophone du produit (le Cameroun est bilingue) ; les mots-clés d'exemple de recherche doivent donner des résultats dans le corpus (à vérifier avant publication).
