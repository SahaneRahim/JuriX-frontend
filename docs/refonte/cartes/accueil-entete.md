**Pièges et risques**
- **Une `<textarea>` n'envoie pas sur Entrée sans JavaScript** : sans script, seul le bouton envoie. Acceptable (le bouton est le contrat P8) ; avec JavaScript, un gestionnaire `keydown` envoie sur Entrée hors composition (`isComposing`) et laisse Maj+Entrée créer une ligne. Le dépôt avait précisément retiré ce gestionnaire sur l'input pour une raison (composition IME) : ne pas la réintroduire sans la garde.
- **`<textarea>` et `role="search"`** : le repère reste sur le `<form>` ; les tests `getByRole('searchbox')` ne trouveront plus rien.
- **Hydratation** : le mode « Assistant IA » par défaut ne peut pas être honnête avant hydratation (le bouton enverrait chercher). Proposition : le serveur rend la bascule dans l'état « Assistant IA » **visuellement**, mais le bouton d'envoi reste nommé « Rechercher » et l'action `/search` ; à l'hydratation, seul le `goto` s'active : aucun décalage de mise en page, mais un lecteur qui touche « Envoyer » **avant** l'hydratation obtient une recherche, pas une réponse. Variante honnête : état initial « Recherche » au serveur et passage à « Assistant IA » au montage (la pastille bouge : décalage visible). À trancher ; préférer la première.
- **Textes tapés et accessibilité** : `aria-hidden` sur la frappe ; ne pas utiliser `aria-live` (bruit). L'animation s'arrête au focus **et** dès que le champ est non vide ; sur mobile, le focus ouvre le clavier : le champ ne doit pas bouger (l'exemple disparaît : pas de saut de hauteur : conserver `height` fixe).
- **`placeholder`** : la maquette utilise `placeholder=" "` et un overlay. L'overlay seul n'est pas lu ni visible sans JS : rendre côté serveur le premier exemple statique (« Exemple : … ») dans l'overlay **sans curseur** ; au montage, l'overlay recommence la frappe. Un `placeholder` natif réel peut s'ajouter pour les lecteurs, mais deux textes superposés doivent être évités.
- **Tuiles : texte du lien** : deux noms (long et court) dans le même lien : sans `hidden`/`sm:hidden` en CSS, le nom accessible est doublé ; avec CSS ils sont exclus de l'arbre d'accessibilité, mais **les tests unitaires qui lisent le HTML serveur** (`accueil.serveur.test.ts`) verront les deux. Attention aussi aux moteurs de recherche. Alternative plus sobre : un seul nom (le court) à tous les écrans (à valider avec le propriétaire).
- **Ordre visuel ≠ ordre DOM** (« Tous les textes » en tête sur mobile via `order`) : l'ordre de tabulation reste celui du DOM ; sous 640 px le focus clavier passe d'abord par les domaines puis par « Tous les textes » : acceptable (WCAG 2.4.3 demande un ordre logique, pas identique) ; sinon mettre « Tous les textes » en premier dans le DOM et utiliser `order-last` à partir de sm.
- **Débordement** : la rangée défilante utilise des marges négatives ; `<main>` est `overflow-x-clip` : vérifier qu'aucun défilement horizontal de page n'apparaît à 320 px (`redimensionnement.spec.ts`).
- **Animations d'arrivée** (la maquette joue `animation-fill-mode: both` avec retards jusqu'à 1,6 s ; en production : `backwards` et des délais ≤ 1 s, `A2` § 2.2 et D9) : en cas d'erreur CSS, le contenu reste invisible ; prévoir un état final par défaut et ne poser `opacity:0` qu'au démarrage de l'animation. Éviter aussi de faire monter la carte de 16 px de haut alors que `{#key $page.url.pathname}` du layout fait déjà `fly` y:16 : double mouvement (le commentaire du dépôt rejette déjà un second fondu). Dans le layout, retirer le `fly` sur `/` au profit des animations de la page ou garder un seul des deux.
- **LCP et CLS** : le titre mot à mot masque le texte jusqu'à 0,5 s (chaque mot part de `translateY(112%)`) : le LCP est mesuré sur la carte ou le titre ; test Lighthouse du dépôt (« Lighthouse comptait ce déplacement ») : vérifier. Polices : `font-display: optional` pour Inter, Literata « instance figée » : la police du titre peut ne pas être chargée : le texte reste lisible.
- **ChatFab** : `masque` calculé par IntersectionObserver ; si le champ unique est suivi par `[data-hero-recherche]`, le bouton reste caché tant que la carte est à l'écran. La barre du bas rend `ChatFab` inutile sous md : un double accès à l'assistant (flottant + onglet) serait un défaut.
- **Barre du bas et pied de page** : prévoir `scroll-padding-bottom` pour que les ancres (`#domaines`) ne passent pas sous la barre ; clavier virtuel : une barre `fixed bottom-0` est repoussée par le clavier sur iOS : la masquer quand un champ a le focus (`:has(:focus)` ou `visualViewport`).
- **Contenu de l'eyebrow** : ne pas animer le nombre (la maquette Mouvement « Compter » le fait, l'accueil non) sauf décision.
- **Incohérence adapter** : `+page.server.ts` (type `@sveltejs/adapter-vercel`) contre README (`adapter-node`) ; ne pas aggraver.
- **Compte du README** : « 315 tests unitaires / 191 e2e » : ces chiffres bougeront ; ne pas les citer.
